# 让布局说话

> 原则：**避免不必要的次要标签和描述。让布局自己说话。**

这是本 skill 的第一原则，也是第 2 节删除动作的全部依据。它不是"少写点字"的风格偏好，而是一个可以当场判定的操作：**删掉这个元素后，信息量是否减少？**

- 减少了 → 它是内容，留下。
- 没减少 → 它是描述的二次编码，删掉，改用结构表达。

## 一、先分清三种文字

| 类型 | 例子 | 处置 |
| --- | --- | --- |
| **内容** | 商品价格、房间面积、订单号、报错原因 | 必须留，且要显眼 |
| **结构** | "分组""第 2 步""共 12 项" | 优先用布局替代；只有布局无法表达时才用文字 |
| **描述** | "在这里你可以管理你的所有项目""强大的团队协作能力" | 默认删 |

一个更快的判据：**把这一屏所有描述类文字遮住，剩下的部分还能读懂吗？** 能，说明这些文字本来就多余；不能，说明该补的是结构（位置、对齐、分组），而不是补一句话。

## 二、什么**不**是次要标签（不要误删）

删减有边界。下面这些即使看起来像"说明"也必须保留：

1. **单位与量纲**：`GB`、`ms`、`元/月`、`含税`。能进列头或后缀就进，但不能没有。
2. **歧义消除**：两个同名按钮（"保存"分别是保存草稿与发布）必须有区分。
3. **防错与不可逆提示**：删除前的后果说明、覆盖已有文件的提醒。
4. **法律与合规**：许可、隐私、来源标注。
5. **真实来源**：数据出处、更新时间、样本量——这是可信度，不是装饰。
6. **空/错/权限状态的下一步**：出错时"为什么"和"怎么办"。
7. **键盘可达性所需的文本**：`aria-label`、`alt`——它们不占视觉空间，不要以"简洁"为由删除。

一个简单的判断顺序：**先问能不能改成结构（位置/对齐/间距），再问能不能并进已有文字（标题、按钮、列头），最后才问能不能删。**

## 三、用布局表达原本由标签表达的六件事

| 想表达 | 不要用 | 改用 |
| --- | --- | --- |
| 分组 | 每个分组一个标题 + 说明 + 外框 | 组间留白（≥ 组内间距的 1.5 倍）、对齐到同一基线 |
| 层级 | 加"重要！"、"注意：" | 字号档位差 ≥ 1.25 倍、位置提前、字重变化 |
| 从属 | "以下属于高级设置" | 缩进、左侧引导线、折叠区、弱化底色 |
| 顺序 | `01 / 02 / 03` | 垂直流向 + 单列、进度条；真有顺序语义时才用序号 |
| 相同性质 | 每项都贴一个类型徽章 | 同一列、同一位置重复出现，本身就是分类 |
| 状态 | 每处都写"已完成/未完成" | 位置固定 + 形状/颜色编码 + 一处图例（仅当编码不直观时） |

**布局的四种基本功**：邻近（近的属于一组）、对齐（共享一条边即共享一种关系）、重复（同一位置=同一含义）、对比（尺寸/字重/颜色只用来标差异）。

## 四、典型改写

### 1. 营销三卡（最常见的 AI 结构）

```html
<!-- 前 -->
<h2>功能特性</h2>
<p>以下是我们为你准备的核心能力</p>
<div class="grid grid-cols-3 gap-6">
  <div class="rounded-2xl shadow-lg p-8">
    <div class="rounded-xl bg-indigo-100 p-3"><svg …/></div>
    <h3>智能同步</h3>
    <p>让你的数据在任何设备上保持实时一致</p>
    <a href="#">了解更多 →</a>
  </div>
  <!-- × 3 -->
</div>
```

删掉：`功能特性`、`以下是我们…`、图标底块、`了解更多`。留下三件真实的事，用列表的密度表达：

```html
<!-- 后 -->
<ul class="divide-y">
  <li class="grid grid-cols-[1fr_auto] items-baseline gap-8 py-4">
    <div>
      <p class="font-medium">改一处，三端同时生效</p>
      <p class="text-sm text-neutral-600">Web、iOS、桌面共用同一份文档，冲突时保留两版并标出差异。</p>
    </div>
    <span class="text-sm tabular-nums text-neutral-500">平均 0.4s</span>
  </li>
  …
</ul>
```

关键差别不在"卡片 vs 列表"，在于**每一条都在说产品独有的事实，而且没有一句话是在解释自己**。

### 2. 设置项满屏帮助文字

```html
<!-- 前 -->
<label>超时时间</label>
<p class="text-xs text-neutral-500">设置请求的超时时间，单位为秒</p>
<input placeholder="请输入超时时间">
```

```html
<!-- 后 -->
<label class="flex items-center justify-between">
  <span>超时</span>
  <span class="flex items-baseline gap-2">
    <input class="w-20 text-right tabular-nums" value="30">
    <span class="text-sm text-neutral-500">秒</span>
  </span>
</label>
<p class="text-xs text-red-600" hidden>需在 1–600 之间</p>  <!-- 只在出错时出现 -->
```

标签从左到右对齐成列，单位做后缀，帮助文字只在**真的会输错**时出现。这一条在桌面上尤其明显：设置面板里的说明文字一多，面板就变成说明书。

### 3. 桌面分组框

WPF 的 `GroupBox` 会画一个带标题的框。若组内每一项已经靠标签自解释，框和标题都是重复编码：

```xml
<!-- 前：框 + 标题 + 每项说明 -->
<GroupBox Header="网络设置">
  <StackPanel>
    <TextBlock Text="代理地址" /><TextBox />
    <TextBlock Text="填写形如 http://host:port 的地址" />
  </StackPanel>
</GroupBox>

<!-- 后：一条分隔线 + 对齐的两列 -->
<Grid Margin="0,16,0,0">
  <Grid.ColumnDefinitions><ColumnDefinition Width="Auto"/><ColumnDefinition/></Grid.ColumnDefinitions>
  <Grid.RowDefinitions><RowDefinition/><RowDefinition/></Grid.RowDefinitions>
  <TextBlock Grid.Row="0" Text="代理" VerticalAlignment="Center" Margin="0,0,12,8"/>
  <TextBox   Grid.Row="0" Grid.Column="1" Margin="0,0,0,8"/>
  <TextBlock Grid.Row="1" Text="端口" VerticalAlignment="Center" Margin="0,0,12,0"/>
  <TextBox   Grid.Row="1" Grid.Column="1"/>
</Grid>
```

## 五、两个自检

1. **遮盖测试**：遮住所有描述类文字再看一次。如果这一屏忽然不知道在讲什么，问题不在措辞，在结构。
2. **删除测试**：截图后逐个元素问"删了会损失什么"。连续三个答不出，说明这一屏是靠描述撑起来的，不是靠结构。

## 六、删过头的信号

删除关也会翻车，出现下面任一情况就回补**结构**而不是回补文字：

- 两个区块贴在一起，读起来像一件事 → 加大组间间距，而不是加标题。
- 用户找不到入口 → 调整位置与视觉重量，而不是加"点击这里"。
- 表格看不出列含义 → 补列头（内容），不是补说明段落。
- 空状态只剩一片空白 → 给一个动作，不是给一段解释。
